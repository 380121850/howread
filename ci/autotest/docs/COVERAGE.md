## 跳过用例定性结论（2026-09-12 真机+代码复核）

首轮 15 个 SKIP 逐一定性：绝大多数是**测试脚本问题**（选择器/入口/状态不对），已修复；仅 FN-16 是**应用侧入口不可达**，FN-25 是**环境限制**。

| 用例 | 定性 | 根因（真机+代码证据） | 处理 |
|------|------|----------------------|------|
| FN-15 翻页模式 | 测试 BUG | 模式菜单实际只有[单页/半页]两项（`DocumentWrapperUI.onModeChangeClick` :1171 绑定，:201 定义；`HorizontalViewActivity` 含"双页"的 4 项菜单是被 wrapper 覆盖的死代码），测试用"双页"判菜单出现→误判未弹出 | 已修：菜单判断改认单页/半页 → **PASS** |
| FN-16 跳页 | **应用侧入口不可达** | 纵向阅读器（`VerticalViewActivity`）默认模式无可用跳页入口：专用入口 `toPage`（→`VerticalModeController.toPageDialog` 真正的[转到页面]对话框）、`thumbnail`、`goToPage1` 在 `document_footer.xml` 均 `visibility=gone`；`bookMenu`(⋮) 无跳页项；长按 `currentSeek` 虽代码绑了 `showDeltaPage`（`DocumentWrapperUI.java:1276`）且 a11y 标记 long-clickable=true，但真机 u2/adb 原生 800/900/1500ms 长按均不弹框（触摸被相邻 SeekBar/纵向文档视图先消费） | 如实 SKIP，备注已更新；应用侧修复建议见下 |
| FN-19 四套主题 | 测试 BUG | `themeColor` 在可折叠容器 `themeConfigContainer` 内（`fragment_preferences.xml:1407` 默认 `visibility=gone`），测试没先点 `themeConfigHeader` 展开就找 `themeColor`（`PrefFragment2.java:385-390` 点 header 才切换展开） | 已修：先展开主题容器 → **PASS** |
| FN-23 AI 配置 | 测试 BUG ×2 | ① 点击监听绑在 `aiConfigValue`（值 TextView，`PrefFragment2.java:955-958`），测试点了粗体标签"AI 大模型(Pro)"点不中；② apiKey 是密码框，回读是掩码点（`•`），`_fill` 拿掩码和明文比较必然失败，且 `el.info` 不暴露 password 属性 | 已修：改点 `aiConfigValue` + `_fill` 按回读内容识别密码框（掩码点数==明文长度）→ **PASS** |
| FN-25 OPDS | 环境限制 | 预置 Gutenberg 源需真外网，测试环境无外网/超时 | 如实 SKIP（环境限制，合理） |
| FN-26/28/29/30 网络协议 | 测试 BUG ×2 + 环境限制 | ① 添加对话框监听绑在区块标题**同一行的[+ 添加]按钮**（`BrowseFragment2.netSectionHeader:1534-1541`），测试点了区块**标题**（无监听）→对话框不打开；② `netSection` 仅根路径可见（`BrowseFragment2:1769` 子目录时 GONE），前序用例把应用留在子目录时 `_browse_root` 的 back 次数不够回不到根 | 已修：新增 `_click_section_add` 点[+ 添加]按钮 + `_browse_root` 加固回根逻辑。**FN-26/27/30 转 PASS**；FN-28/29 填 SMB/SFTP 密码框时 MIUI 安全自动填充（`com.miui.contentcatcher`）干扰致 uiautomator JSON-RPC -32002 崩溃（AGENTS.md 已知坑#21），已加 u2 异常保护如实 SKIP（非功能缺陷，换无 MIUI 自动填充的设备/关自动填充后可跑通） |

**首轮 8 FAIL + 15 SKIP 的复核结论**（详见上方「跳过用例定性结论」表）:
- 8 个 FAIL 全部是**测试脚本问题**（MI9 应用语言被切到英文而选择器只认中文 + 个别选择器/入口不对），修复后全部转 PASS，无一应用缺陷。
- 15 个 SKIP 中 8 个是**测试脚本 BUG**（FN-15/19/23/26/27/30 等，选择器/入口/状态不对），修复后转 PASS；FN-16 是**应用侧入口不可达**（纵向阅读器无可用跳页入口）；FN-25 是**环境限制**（无外网）；FN-28/29 是**环境限制**（MIUI 自动填充崩 u2）。

**最终 6 个 SKIP 的合理原因**:
- FN-07 TTS：TTS 入口在当前 UI 不可达（既有 SKIP，保留）
- FN-13 标签：长按菜单无[添加标签]入口（应用 UI 限制）
- FN-16 跳页：纵向阅读器无可用跳页入口（应用侧，见定性表）
- FN-25 OPDS：测试环境无外网，Gutenberg 源不可达
- FN-28/29 SMB/SFTP：MIUI 安全自动填充干扰密码框致 u2 JSON-RPC 崩溃（换设备/关自动填充可跑通）

## 验证结论

L1 自动化测试覆盖了核心功能的主要路径，**最终 24 PASS / 0 FAIL / 6 SKIP（通过率 80%，24/30）**。首轮报出的 8 个 FAIL 经真机+代码逐一复核，**全部是测试脚本问题（非应用缺陷）**，修复后转 PASS；15 个 SKIP 中 8 个同样是测试脚本 BUG，修复后转 PASS。

剩余 6 个 SKIP 均为**合理跳过**：FN-07/FN-13 是应用 UI 入口限制，FN-16 是应用侧跳页入口不可达（已给出应用侧修复建议），FN-25 是无外网环境限制，FN-28/29 是 MIUI 自动填充干扰自动化（环境限制，非功能缺陷）。

功能层面，核心阅读（开书/书签/目录/字号/主题/翻页）、Pro 功能（笔记/AI 配置/阅读统计）、网络协议（WebDAV 浏览+同步/远程书在线打开）全部验证通过，满足基础可用性验收要求。唯一需应用侧关注的是 **FN-16 跳页入口在纵向阅读器不可达**，建议按定性表中的代码线索排查 `currentSeek` 长按事件被相邻视图消费的问题。
